# EneTrend

Health Connectのデータを読み取り、カロリー収支と体重変化を同じ時間軸で確認するAndroidアプリです。食事・運動・体重の入力やHealth Connectへの書き込みは行いません。

## 利用を始める

検証の基準環境はAndroid 14（API 34）です。Android 13の利用は想定しておらず、手動検証は省略しています。ビルド設定上のminSdkは28ですが、すべての端末での動作を検証したものではありません。

1. 記録元のアプリからHealth Connectへ栄養・総消費カロリー・体重を連携します。
2. EneTrendを開き、3種類の**読み取り権限**を許可します。
3. グラフ下で表示期間（7・14・30日、初期値30日）と移動平均期間（7・14・30日、初期値7日）を選びます。
4. グラフをタップするかスライダーを動かすと、その日の数値・欠測・推定の詳細を確認できます。

「再確認」「Health Connect の設定」は画面下部にあります。長い画面では下までスクロールしてください。権限不足時も下部に配置されます。記録の追加・権限変更後はアプリへ戻るか「再確認」で再取得できます。利用不可・権限不足・読み込み中・取得失敗は、データなしとは別に表示します。

端末のライト／ダーク設定と文字サイズに追従します。アプリ内の独自テーマ設定はありません。

## グラフの読み方

```text
日別カロリー収支 = 摂取カロリー − 総消費カロリー
負 = 消費超過、正 = 摂取超過
```

1つのプロット・共通の日付軸に次の4系列を表示します。

| 系列 | 表示 |
| --- | --- |
| 日別収支 | 棒。正は淡い暖色、負は淡い寒色、0は中立色。左軸kcal |
| 期間累積収支 | 折れ線。表示期間の開始時点を0 kcalとして期間内だけ累積 |
| 体重 | 点と折れ線。右軸kg |
| 体重移動平均 | 点マーカーなしの点線。右軸kg |

表示期間を変えると累積も計算し直すため、同じ日でも期間累積収支は変わります。全履歴の通算ではありません。

期間累積は右軸の1 kg分の高さを7,000 kcal分として位置合わせします。累積0の高さは期間内の最初の実測体重、実測がなければ最初の補間体重です。どちらもない場合、累積は独立した尺度で表示します。累積のkcal目盛りは省略し、実際のkcal値は日付詳細に表示します。これは表示上の位置合わせであり、体重予測ではありません。換算係数の設定UIは未実装です。

## 欠測・補間・移動平均

- 日付は端末のタイムゾーンに従います。体重は同じ日の最後の測定を代表値にします。
- 摂取カロリーの未記録は欠測です。0 kcalへの置換や推定補完はしません。
- 総消費カロリーと体重は、前後の記録に挟まれた連続6日以内の欠測を線形補間します。7日以上の欠測や片側しか記録がない区間は補間・外挿しません。
- 補間値は白抜き・破線や日付詳細で区別します。補間を使用した収支にも推定であることを示します。
- 摂取または消費が欠測なら日別収支は未算出です。その日以降の期間累積も未算出とし、計算できた日の小計を別に表示します。小計を完全な累積値として扱いません。
- 移動平均は当日を含む直近の暦日を対象に、実測の日代表値だけから計算します。補間値や欠測日の0は含めません。実測日数が少ない場合は日数不足を示し、7日以上測定が空くと平均表示も停止します。
- 孤立した移動平均値は点マーカーを描かず、数値を日付詳細で確認できます。欠測を跨いで線を結びません。
- 今日の記録は途中です。記録がある日も、記録漏れがないことを保証しません。Health Connectの取得可能期間に制限がある場合、開始付近の平均・補間は取得できた記録だけに基づきます。

## プライバシー

使用するのは`NutritionRecord`、`TotalCaloriesBurnedRecord`、`WeightRecord`の読み取り権限のみです。健康データをアプリのファイル・DBへ永続保存せず、ログ出力や外部送信もしません。アプリにはINTERNET権限がありません。画面復元用には表示期間・平均期間・選択日を保持します。

権限はHealth Connectの設定で変更・取り消せます。詳しい説明は画面下部の「データの利用とプライバシー」でも確認できます。

## APKの入手

[GitHub Actions](https://github.com/puvon/enetrend/actions/workflows/debug-apk.yml)の成功した「Build debug APK」runを開き、Artifactsから`enetrend-debug-<commit SHA>-<run attempt>`をダウンロードして展開します。GitHubへのログインが必要です。

masterへのpush（mergeによる更新を含む）でdebug APKをビルドし、artifactを14日間保存します。期限後は対象のartifactを取得できません。GitHub Releaseへの公開は行いません。

これはdebug版です。署名鍵はCI runnerで生成されるため、ローカル版や別runのAPKと署名が異なる場合があります。署名が異なると上書きインストールできません。必要に応じて既存のEneTrendをアンインストールしてから入れ直してください。その場合、アプリの設定・権限は再設定が必要です。

## 開発・ビルド

Windows / PowerShellを基準とします。Git運用・作業範囲は[AGENTS.md](AGENTS.md)、計画と検証履歴は[TODO.md](TODO.md)を参照してください。

- Android SDK Platform 37.0（SDKパッケージIDは`platforms;android-37.0`）とBuild Tools 36.0.0
- JDK 25（Gradle daemon）。Java/Kotlinのソース互換設定はJava 11
- リポジトリのGradle Wrapper。バージョンは`gradle/wrapper/gradle-wrapper.properties`に定義
- Android StudioのSDK設定から作成されるローカルの`local.properties`。Gitへ追加しない
- pre-commitとgitleaksをPATHから実行できる環境

```powershell
.\gradlew.bat test
.\gradlew.bat lint
.\gradlew.bat assembleDebug
pre-commit run --all-files
```

生成先は`app/build/outputs/apk/debug/app-debug.apk`です。pre-commitにはgitleaksが設定されています。シークレット・署名鍵・`.env`を追加せず、hookを迂回しないでください。

API 34エミュレータを起動し、必要な読み取り権限とテスト用データを用意してAndroidテストを実行します。

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest
```

実Health Connectの読み取りテストは利用可否・権限を前提とし、回転テストは既存の読み取り可能なデータも必要です。空データ・取得失敗などの画面は、テスト用データソースを使うCompose UIテストでも確認します。
